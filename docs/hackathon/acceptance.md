## Приёмка новых функций

1. Войти как hack_processor, открыть /recurring/?mode=demo: у основной карточки три повтора.
2. Открыть основную карточку и повтор; переходы доступны в обе стороны.
3. Ограничить доступ к одному концу связи в тестовой среде: ни ссылка, ни скрытое число не раскрываются.
4. Повторно открыть дубликат: действующая связь перестаёт участвовать в сводке.
5. Включить рабочий режим: синтетические карточки отсутствуют.
6. Задать период: он ограничивает дату подачи повторов, не основной карточки. Неизвестные даты учитываются только без периода.
7. Повторить загрузку демо: карточки, решения и пароли не сбрасываются.

Сводка считает текущие прямые связи; транзитивная кластеризация, динамика и исторический срез связей не заявляются. Нагрузка на миллион карточек и другие численные NFR из внутренней specification.md — отдельные цели пилота, не требования исходного хакатонного брифа.

## Удобство защиты

`/demo/` — стартовая страница, доступная после входа только в демо-режиме. Карточки ограничены правами текущего пользователя. `/requests/{uuid}/demo-result/` открывает учебную памятку только для доступного завершённого демо-примера. `scripts/rehearse.sh` создаёт свежую БД без сброса истории существующих показов.
