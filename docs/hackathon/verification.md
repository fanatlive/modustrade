## Воспроизведение

Для локальных тестов:

```bash
export DEBUG=1 DEMO_MODE=1 DB_ENGINE=sqlite
.venv/bin/python manage.py test --noinput
.venv/bin/python manage.py check
.venv/bin/python manage.py makemigrations --check --dry-run
.venv/bin/python -m ruff check .
.venv/bin/python -m mypy
```

Для PostgreSQL задать DB_ENGINE=postgres, POSTGRES_HOST/PORT/DB/USER/PASSWORD отдельного тестового сервера. Пользователь тестов должен иметь право создавать тестовую БД; не использовать рабочую БД. Выполнить тот же manage.py test.

Для браузера подготовить отдельную БД с именем, заканчивающимся на `_browser`, выполнить migrate и load_demo, установить requirements-dev.txt и Chromium (`python -m playwright install chromium`), затем запустить `python tests/run_browser_remediation.py`. Runner добавляет набор защиты и владеет сервером на порту 8765; занятый порт не перехватывает. Допускается SQLite только с абсолютным SQLITE_PATH, оканчивающимся на `_browser.sqlite3`; этот режим не заменяет проверки PostgreSQL.

## Ограничения и оставшиеся действия

Реальный пользовательский опыт, бизнес-эффект, согласование ролей и сроков не проверены: см. [отдельный план](user-validation.md). Репетиции команды и резервное видео не проведены. Нагрузка, промышленная конфигурация, восстановление и внешняя интеграция в рамках этой доработки повторно не испытывались. Совместимость dev.sh с Linux проверена по синтаксису; фактический чистый запуск выполнен на macOS. Основная локальная БД проекта не использовалась для браузерных записей.
