# Проект регламента ответственности

Это предлагаемый порядок для согласования, а не утверждённый регламент компании. До пилота компания назначает владельца процесса, координаторов и заместителей для каждой очереди, включая конфиденциальную.

| Ситуация | Ответственный | Действие и контроль |
| --- | --- | --- |
| Новое обращение | Исполнитель очереди | Начать рассмотрение, дать содержательный ответ; автор видит статус |
| Маршрут отсутствует или неоднозначен | Координатор резервной очереди | Проверить категорию, переназначить с причиной; сроки не обнулять |
| Резервная очередь недоступна | Администратор и владелец процесса | Восстановить допустимого обработчика; система не сообщает об успешной регистрации при отказе |
| Не хватает сведений | Исполнитель | Задать конкретный вопрос и срок; после ответа продолжить обработку |
| Срок уточнения истёк | Координатор | Проверить напоминание; продолжить, продлить с причиной либо закрыть по регламенту; молчание не считается отказом автоматически |
| Просрочен ответ или выполнение | Координатор, затем руководитель | Ежедневно проверить просрочки, причину и план; уведомления пока только внутри системы |
| Отпуск, блокировка или смена роли | Администратор и координатор | До отключения проверить открытые назначения; передать через интерфейс либо reconcile_assignments сначала без --apply, затем с --apply |
| Нет допустимой замены | Владелец процесса | Назначить сотрудника с необходимыми правами; не обходить конфиденциальность |
| Повтор проблемы | Исполнитель | Проверить смысл, выбрать доступную основную карточку; её владелец отвечает за общую причину |
| Исполнение завершено | Исполнитель, автор | Записать результат и подтверждение; автор читает результат и может открыть повторно в пределах срока |
| Сбой уведомлений | Координатор и эксплуатация | Проверить очередь ошибок, устранить причину, повторить доставку с основанием |

Демо-сроки и рабочий календарь не являются согласованными SLA. До пилота утвердить сроки ответа и решения, правила замещения и канал срочной эскалации. Команда reconcile_assignments не запускается автоматически при отключении сотрудника; её выполнение должно входить в процедуру изменения учётных записей.

Администратор приложения, суперпользователь и администратор БД — разные уровни полномочий. Прикладные ограничения не обеспечивают недоступность данных для оператора инфраструктуры. Организационные полномочия утверждаются отдельно.
