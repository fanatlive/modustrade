# Концепция уведомлений через Битрикс24

Статус: проект интеграции. Приложение сейчас доставляет уведомления только внутри системы. Вызовы Битрикс24 и получение внешних подтверждений не реализованы. Возможности и ограничения API конкретного портала необходимо проверить перед реализацией.

## Цель и направление

При изменении обращения сотрудник получает краткое уведомление и ссылку, чтобы не проверять приложение вручную. Первый этап односторонний: система обращений → корпоративный канал Битрикс24. Источник истины по статусу, решению и доступу — система обращений; ответ через Битрикс24 и изменение карточек извне не предусмотрены.

## Предлагаемые данные

| Поле | Назначение |
| --- | --- |
| Идентификатор события и доставки | Идемпотентность и диагностика |
| Корпоративный идентификатор получателя | Сопоставление с локальным аккаунтом по утверждённому справочнику |
| Номер обращения и нейтральный тип события | Например, «Есть обновление обращения» |
| HTTPS-ссылка на карточку | Повторная авторизация и проверка доступа при открытии |

Не передавать описание, внутренние заметки, текст решения и вложения. Для конфиденциальных обращений допустимость даже номера и самого факта обращения согласовать отдельно; до согласования не отправлять их наружу.

## Предполагаемый способ взаимодействия

Адаптер worker обрабатывает отдельную доставку после фиксации бизнес-транзакции. Использует согласованный серверный API и учётные данные с минимальными правами, проверяет актуальность доступа перед отправкой. Ошибки повторяются с задержкой, исчерпанные попытки показываются координатору. Успешный ответ API означает принятие доставки, а не прочтение сотрудником. Повторная обработка не должна создавать повторное сообщение; ограничения внешнего API могут потребовать отдельного механизма дедупликации.

## Что уточнить у компании

Версия и тип портала, доступный способ авторизации, ограничения API и сети, владелец интеграции, источник идентификаторов пользователей, жизненный цикл аккаунтов, разрешённые данные, правила для конфиденциальных обращений, лимиты доставки и хранение технических журналов. Проверить, можно ли решить задачу штатной настройкой Битрикс24 без отдельного приложения.

## Будущая приёмка

Проверить доставку в тестовый портал, отзыв доступа до отправки, повтор после тайм-аута, блокировку получателя, исчерпание попыток и отсутствие конфиденциального текста в сообщениях и журналах. Эти проверки ещё не выполнялись.
