# Исправления и повторный аудит проекта

**Дата:** 11 ноября 2026 года, Asia/Bishkek.
**Объект:** система обратной связи «Модус Трейд», выбранный MVP.

## Заключение

Дефекты F01–F23 исходного [аудита](audit-2026-11-11.md) устранены. Дополнительные
подтверждённые замечания независимых повторных проверок также исправлены и
проверены регрессиями. В проверенном контуре не осталось открытых замечаний P1/P2.
Это заключение относится к описанным сценариям, исходным данным и локальному
размещению; оно не означает доказательство отсутствия любых ошибок.

Основной стенд обновлён и доступен по `http://127.0.0.1:8000/`. Сохранены 21
существующая карточка, включая 20 исходных, исходные снимки, пароли, очереди,
членство и маршруты. Повтор импорта создал 0 карточек, сохранил 20 исходных и
не обнаружил конфликтов. Рабочая БД не подменялась тестовой. Нагрузочные,
браузерные и независимые проверки выполнялись отдельно.

## Что дополнительно обнаружил повторный аудит

1. **Ответ автора при потере исполнителя.** Ответ теперь сохраняется. При необходимости
   реализация получает подходящую замену либо ожидает назначения координатором с
   сохранёнными решением, критерием и планом. Отзыв/дубликат не обходят согласование.
   Повторное открытие также сохраняется при отсутствии доступных сотрудников.
2. **Исторические JSON NULL и будущая дата.** Legacy-переходы восстановлены без
   ошибочного NEW; будущий as_of отклоняется. Некорректные дополнительные роли
   не дают полномочий и не попадают в список исполнителей.
3. **Семантика новой версии датасета.** Изменённая строка не наследует результат
   канонической A-008. Проверяются тип/статус и отпечаток строки; спорные данные
   получают REVIEW и флаги. Все 180 исходных значений сохранены.
4. **Эксплуатация.** Исправлены удаление HTTPS-заголовка Waitress, повторное разрешение
   адреса web в nginx, Host проверки готовности, слабые примеры owner/runtime
   паролей и лишние права существующей роли, включая владение в другой БД.
5. **Копии.** Manifest записывается атомарно; неполная/повреждённая пара не вытесняет
   последнюю пригодную. Проверяются место перед восстановлением, наличие архива,
   размер и согласованность метаданных. Возраст считается от snapshot.
6. **Наблюдаемость.** Backoff не скрывает действительную задержку уведомления.
   Query поиска не записывается в proxy access log. Метрики не содержат тексты
   карточек и требуют отдельный токен.

Независимые отчёты сохраняют первоначальные находки и последующее доказательство
закрытия: [domain](final-audit-domain-review.md), [data/ops](final-audit-data-review.md),
[UI](final-audit-ui-review.md). Ранний исходный аудит не переписан задним числом.

## Архитектурные и эксплуатационные улучшения

Сохранён модульный монолит Django/PostgreSQL. Для объёма MVP это уменьшает число
распределённых точек отказа; отдельный worker выполняет transactional outbox.
Маршруты версионируются без переписывания прошлых условий. DTO и матрица команд
задают явные границы валидации. Шаблон карточки разделён на небольшие части.

Поиск использует STORED tsvector/GIN и индексы номеров; БД пересчитывает документ
при изменении исходного текста. Отключение JIT обосновано EXPLAIN: на проверенном
COUNT компиляция занимала 38–40 мс, а сам запрос без неё — около 6–7 мс.
Истории ограничены страницами 50 сообщений / 50 событий / 10 циклов / 25 уточнений.
Дальние страницы используют OFFSET; их стоимость на экстремальной истории
одной карточки отдельно не аттестована.

Добавлен профиль DEBUG=0/DEMO_MODE=0 с TLS, закрытым web/DB, DML-ролью выполнения,
отдельными миграциями, heartbeat, безопасными агрегатами, ротацией логов и backup.
Секреты, ключи, базы, копии и рабочие артефакты исключены из Git/Docker context.
CI содержит PostgreSQL, миграции, регрессии, браузер, проверку зависимостей,
базовые правила Ruff, strict DTO mypy и сборку. Удалённый GitHub-run не выполнялся.

Перед обновлением сохранена копия. После обновления автоматическая копия
восстановлена в новую временную БД: **29 таблиц, контрольные подписи совпали,
constraints валидны; 2,742 с**. Временная БД удалена. Это время тестового восстановления
малой базы, а не RTO всей инфраструктуры. Backup работает каждые 600 секунд;
свежесть и полнота метаданных контролируются отдельно.

## Проверки и нагрузка

- PostgreSQL 17 / Python 3.13: **150 тестов, OK**.
- SQLite / Python 3.14: **141 пройден, 9 PostgreSQL-проверок пропущено**.
- Chromium: **13 сценариев, 0 ошибок JavaScript**.
- TLS/production: **7 проверок**, включая настоящий HTTPS-вход и безопасный access log.
- pip-audit: известных уязвимостей в 10 разрешённых runtime/dev пакетах не найдено
  на дату проверки. Это не сканирование всех пакетов базовых ОС-образов.
- check, check --deploy, makemigrations --check, pip check, Ruff, mypy, Docker build
  и обе Compose-конфигурации пройдены.

Непрерывная нагрузочная приёмка завершена: **36 000 запросов за 1800.1 с,
ошибок 0, пропусков 0**, фактический поток 20.0 запросов/с.
Подготовлено 10 000 карточек и 100 000 событий, использованы 100 авторизованных
сессий. Смесь: 70% просмотр / 20% поиск / 10% запись.

| Операция | Запросов | p95, мс | Предел, мс |
| --- | ---: | ---: | ---: |
| Просмотр | 25200 | 222.4 | 1000 |
| Поиск | 7200 | 354.4 | 2000 |
| Запись | 3600 | 335.49 | 1500 |

Пороги соблюдены **на этом объёме**. Все исходные файлы приложения совпали с
зафиксированным SHA-256; тестовая БД и принадлежащий запуску сервер удалены.
Полный [JSON протокол](test-evidence/load-30min.json) содержит планы SQL и среду.
Это HTTP/Waitress на локальном Python 3.14, DEBUG=1; worker не входил в смесь.
Функциональная контейнерная приёмка отдельно выполнена на Python 3.13.
Это не нагрузочная аттестация рабочего TLS-размещения.

Первый большой прогон обнаружил перегрузку и был остановлен; его результат сохранён
как неуспешный, отсутствующий p95 не восстановлен вымышленной оценкой. После
оптимизации короткая проверка дала 1 200 запросов без ошибок: p95 158/273/346 мс
для просмотра/поиска/записи. Окончательная приёмка использует новую замороженную
версию, включает последнюю пагинацию и имеет отдельный отчёт.

## Что нельзя считать подтверждённым

Полный объём **1 млн карточек / 10 млн событий** не запускался: защитная оценка
требует около 51 ГиБ свободного места; при проверке было доступно 9,3 ГиБ. Отказ произошёл
до создания БД. Меньший набор не доказывает целевую ёмкость.

Доступность 99,5% за месяц, RPO ≤15 мин/RTO ≤2 ч при физической потере хоста,
защищённое внешнее хранилище копий и промышленная сеть требуют испытаний на
выбранной инфраструктуре. Локальная копия не защищает от утраты компьютера.
На большом объёме интервал pg_dump необходимо измерить и при необходимости
перейти к base backup + непрерывному WAL/PITR.

До реальных данных владелец утверждает календарь, роли, размещение, контакты
дежурных и сроки хранения. Для хранения подготовлен безопасный retention_report;
деловые карточки автоматически не удаляются без определённой политики.
Вложения, SSO, анонимность и реальные 1С/Битрикс-интеграции остаются за принятой
границей MVP. Демонстрационные тексты не превращены в обязательство построить
перечисленные в них корпоративные системы.
