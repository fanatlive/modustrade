# Поиск обращений

PostgreSQL хранит `Ticket.search_document` как persisted GeneratedField типа
tsvector. Значение вычисляется самой БД из description и proposed_solution при
записи; обычные save/update, bulk_create/bulk_update и импорт не требуют отдельной
синхронизации. Явный `'russian'::regconfig` исключает зависимость от конфигурации
сеанса и позволяет использовать immutable-выражение generated column.

GIN `ticket_search_document_gin` индексирует готовый документ. Поиск и ранжирование
используют колонку через alias/F; текст не токенизируется заново для каждой строки
при чтении. Старый функциональный GIN удаляется последующей миграцией. Поиск по
номеру и source_record_id сохраняет отдельные триграммные индексы. Все ветви
применяются внутри уже разрешённой пользователю выборки; поиск не расширяет доступ.

На SQLite generated column содержит пустую строку, а локальный демонстрационный
поиск использует icontains. Морфология и полнотекстовая производительность
проверяются на PostgreSQL. Обычные HTML-выборки откладывают получение вектора,
чтобы не передавать его с каждой карточкой.

Бизнес-команды исключают generated fields из явного UPDATE. Для чтения изменённого
значения после save используется refresh_from_db, согласно
[контракту Django GeneratedField](https://docs.djangoproject.com/en/5.2/ref/models/fields/#generatedfield).
Миграция добавления persisted column обрабатывает существующую таблицу и требует
планирования места и времени; перед применением к большой рабочей БД необходимы
резервная копия и измерение миграции на сопоставимом объёме.

`tests/test_search_document.py` проверяет обе СУБД, запись двух исходных текстов,
bulk-операции, изменения JSON без потери вектора, бизнес-команду и физическую схему.
