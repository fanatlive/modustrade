## Повторная проверка

```powershell
docker compose run --rm --no-deps migrate python manage.py test tests --noinput
docker compose exec -T web python manage.py check
```

Для браузера установите зависимости `requirements-dev.txt` и Chromium командой
`python -m playwright install chromium`. Подготовьте отдельную демо-БД с именем,
оканчивающимся на `_browser`, выполните в ней migrate и load_demo, затем задайте
DB_ENGINE=postgres, POSTGRES_DB и POSTGRES_PORT и запустите:

```powershell
.\.venv\Scripts\python.exe tests/run_browser_remediation.py
```

Скрипт отказывается занимать используемый порт и завершает только созданное им
процесс по его handle. Скриншоты и JSON-результат сохраняются в игнорируемую папку
`test-results`. Скрипт создаёт новое демонстрационное обращение при каждом запуске.

## Не подтверждено этими проверками

Нагрузочные цели на миллион карточек, месячная доступность 99,5%, RPO/RTO при
потере хоста, промышленный SSO и подключение корпоративных систем требуют
отдельных испытаний. Загрузки файлов в этом MVP нет. Проверка настроек не заменяет
проверку сетевого периметра, TLS и политики реальных данных.

TLS проверяется реальной цепочкой nginx → Waitress → Django в отдельном
профиле `*_probe`: `tests/production_probe.py`. Восстановление архива проверяется
в новой временной БД командой `ops/backup.py restore-verify`. Тесты, создающие БД
и роли, запускаются от migrate/владельца схемы, а не от ограниченной роли web.
