# HTTP интерфейс MVP

Текущий интерфейс возвращает серверные HTML-страницы. Отдельный публичный JSON API
и OpenAPI-публикация не заявляются. Внешние интеграции требуют отдельного контракта.
Бизнес-команды вынесены в `feedback.services` и не зависят от HTML-форм.

| Метод и путь | Назначение |
| --- | --- |
| GET / | Поиск и список в области доступа пользователя |
| GET /queue/ | Рабочая очередь обработчика |
| GET /requests/new/ | Форма подачи с ключом идемпотентности |
| POST /requests/new/ | Регистрация и 302 на сохранённую карточку |
| GET /requests/{uuid}/ | Карточка с фильтрацией сообщений и истории |
| POST /requests/{uuid}/command/ | Бизнес-команда с `command` и `version` |
| GET /requests/{uuid}/canonical/?q=...&page=... | Поиск доступных основных карточек для связи дубликата |
| GET /requests/{uuid}/similar/ | Подсказки похожих карточек в текущей области доступа |
| GET /analytics/?mode=demo | Демонстрационные показатели |
| GET /analytics/?mode=production | Показатели с исключением всех демо-карточек |
| GET /notifications/ | Только доступные уведомления текущего пользователя |
| POST /notifications/{id}/read/ | Прочтение своего доступного уведомления |
| GET /deliveries/failed/ | Ошибки доставки в области координатора |
| POST /deliveries/{id}/retry/ | Повтор неудачной доставки с причиной |
| GET, POST /settings/ | Настройки для администратора приложения |
| GET, POST /accounts/login/ | Вход |
| POST /accounts/logout/ | Выход |
| GET /health/ | Проверка приложения и соединения с БД |
| GET /health/worker/ | Актуальный heartbeat обработчика |
| GET /operations/metrics/ | Агрегаты эксплуатации по Bearer-токену |

Изменения требуют действующей сессии и CSRF-токена. Успех команды — 302 на карточку;
422 означает ошибку данных или недопустимый переход, 409 — устаревшую версию или
конфликт содержимого ключа создания. 403 применяется к запрещённой операции,
404 — к недоступной карточке. Ограничение частоты возвращает 429 и Retry-After.

Команды: start, assign, approve, decline, acknowledge, ask_info, answer_info,
resume_info, extend_info, reclassify, implement, reopen, withdraw, duplicate, no_response, comment. Для approve обязательны
reason, criteria и будущий plan_due_at; implement требует result и evidence.
Комментарий содержит message и visibility=public/internal. На сервере повторно
проверяются полномочия, состояние, версия и связанные объекты.

Ключ `idempotency_key` создаётся при открытии формы и повторяется при повторной
отправке. В текущем MVP записи ключей не удаляются; повтор одинакового содержимого
возвращает ту же карточку. Исходные идентификаторы импорта уникальны независимо
от ключей пользовательских команд.

Ограничение частоты хранится в общей БД: по умолчанию 20 попыток входа за пять
минут с одного IP и 10 по нормализованному логину (совместно для accounts/login
и admin/login), 30 созданий в час и 120 команд в минуту на учётную запись.
При TRUST_PROXY=0 используется REMOTE_ADDR; доверенная конфигурация описана
в [эксплуатации](operations.md). Хранятся хэши идентификаторов лимитов.

Аналитика принимает `mode`, `date_from`, `date_to` (когорта по дате подачи) и
`as_of` (срез на момент). Доступ всегда проверяется по актуальным правам, в том
числе для исторического среза. Карточки без даты показываются отдельным счётчиком,
а не получают дату импорта. Ограничения legacy-срезов указаны на странице.

Полные переходы и обязательные поля: [матрица команд](command-matrix.md).
