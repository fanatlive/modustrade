# Матрица бизнес-команд

Источник исполняемых проверок — `feedback/services.py:execute_command`; допустимые
поля описаны в `feedback/contracts.py`. Отображение кнопки не заменяет серверную
проверку. Любая команда требует действующую учётную запись, доступ к карточке и
точную `expected_version`. Изменение карточки, событие и доставки фиксируются одной
транзакцией. Конфликт версии возвращает 409, нарушение бизнес-правила — 422,
отсутствие полномочий — 403. Некорректный или недоступный основной UUID дубликата
не раскрывает чужую карточку.

«Обработчик» означает действующего исполнителя/участника/владельца очереди с ролью
processor, coordinator или manager; для конфиденциальной карточки нужен допуск.
«Координатор» дополнительно требует coordinator/manager. Superuser имеет служебный
доступ. Авторство само по себе не даёт права обработки; внутренние заметки закрыты
для автора даже при совмещении ролей.

| Команда | Начальное состояние → результат | Полномочия | Обязательные поля и ограничения |
| --- | --- | --- | --- |
| `start` | NEW → REVIEW | Обработчик | Действующий подходящий исполнитель; начинающий разбор назначается при недоступности прежнего, если сам подходит |
| `assign` | Любое активное → то же | Координатор текущей и целевой очереди | `reason`; `queue_id` (иначе текущая), `assignee_id` (может быть пустым до реализации). В реализации и ожидании с возвратом в IN_PROGRESS исполнитель обязателен. Уровень очереди, роль, членство и допуск исполнителя проверяются заново |
| `approve` | REVIEW → IN_PROGRESS | Обработчик | Только PROBLEM/SUGGESTION; `reason`, `criteria`, будущий `plan_due_at`; подходящий исполнитель |
| `decline` | REVIEW → CLOSED/DECLINED | Обработчик | Только PROBLEM/SUGGESTION; мотивированный `reason` |
| `acknowledge` | REVIEW → CLOSED/ACKNOWLEDGED | Обработчик | Только PRAISE; `reason` с результатом обработки |
| `ask_info` | REVIEW/IN_PROGRESS → WAITING_INFO | Обработчик | `question`; `due_at` необязателен, по умолчанию +40 рабочих часов, максимум +40. Одновременно один активный вопрос |
| `answer_info` | WAITING_INFO → сохранённое состояние возврата или REVIEW для восстановления назначения | Только автор | `message` (совместимый ключ `response` поддержан); активный вопрос. Доступность исполнителя не препятствует сохранению ответа |
| `resume_info` | WAITING_INFO → сохранённое состояние возврата или REVIEW для восстановления назначения | Координатор | `reason`; закрывает ожидание без подмены ответа автора и завершает фактическую паузу; действует безопасный возврат при недоступном исполнителе |
| `extend_info` | WAITING_INFO → WAITING_INFO | Координатор | `reason`, будущий `due_at`, позднее прежнего и не далее +40 рабочих часов от продления. Остаток общей паузы не превышает 40 рабочих часов; новое поколение напоминания |
| `implement` | IN_PROGRESS → CLOSED/IMPLEMENTED | Обработчик | Только PROBLEM/SUGGESTION; предыдущее APPROVED, сохранённый критерий; `result` и `evidence` |
| `comment` | Любое активное → то же | Автор или обработчик | `message`; `visibility=public/internal` (по умолчанию public). Internal требует доступа к внутренним сообщениям и не считается первым ответом |
| `withdraw` | Любое активное → запрос согласования либо CLOSED/WITHDRAWN | Автор; согласование — координатор | `reason`. В IN_PROGRESS и ожидании с возвратом туда автор создаёт запрос согласования. Координатор закрывает только при наличии такого запроса в текущем цикле |
| `duplicate` | REVIEW → CLOSED/DUPLICATE | Обработчик | `reason`, доступный `canonical_id`; запрет самоссылки и циклов. Изменения графа сериализованы; прежняя связь архивируется после повторного открытия |
| `no_response` | WAITING_INFO → CLOSED/NO_RESPONSE | Координатор | `reason`; истёк срок, зафиксирована эскалация, напоминание фактически доставлено автору и после доставки прошло не менее 8 рабочих часов |
| `reopen` | CLOSED → REVIEW, новый цикл | Автор в пределах 40 рабочих часов после закрытия; позднее — координатор | `reason`; календарь прошлого цикла определяет окно. Старые решение, результат, подтверждение и сроки сохраняются; новый цикл использует новую политику. При отсутствии подходящего исполнителя повторное открытие сохраняется без назначения в исходной очереди; до одобрения координатор назначает исполнителя |
| `reclassify` | Любое активное → то же | Координатор | `reason`; `category_id`, `effective_priority`, `request_type` необязательны (текущие значения по умолчанию). Действующая категория и допустимые enum. Тип меняется только до решения. Маршрут пересчитывается, reported_priority не меняется; SLA пересчитывается от начала цикла по его календарю с сохранением использованной паузы и прежнего нарушения |

Текстовые обязательные поля не могут состоять из пробелов; максимум 10 000 символов.
Повторная команда с устаревшей версией не выполняется. Команда над CLOSED, кроме
`reopen`, отклоняется. Продление уточнения не переносит план реализации автоматически.
Положительный отзыв не допускает одобрение, отказ и реализацию и не увеличивает
показатель реализованных улучшений.

Регистрация выполняется отдельным `create_ticket`: категория, тип и описание от
10 до 10 000 символов, допустимые приоритет/конфиденциальность, ключ идемпотентности
1–128 символов. Повтор того же ключа с тем же содержимым возвращает прежнюю карточку;
с другим содержимым — 409. Номер содержит 28 UUID hex-символов; конфликт уникальности
повторяется в savepoint до пяти раз, затем возвращается контролируемая 503.

`retry_delivery(actor, outbox_id, reason)` — отдельная операция координатора своей
области; доступна только для failed. Для внутреннего события нужен внутренний
доступ. Сбрасывает попытки, сохраняет идентичность доставки, пишет внутреннее
событие с причиной и прежней диагностикой. Уникальность Notification по outbox
не допускает повторного пользовательского уведомления.

`reconcile_assignments` по умолчанию только показывает недействительные назначения.
Режим применения использует обычную команду assign с причиной и версией. Когда
подходящего кандидата нет, запись остаётся в отчёте для координатора; назначение
произвольному пользователю не производится.

`revise_routing_rule` создаёт следующую версию и деактивирует старую. Условия,
приоритет, номер версии и предшественник старого правила неизменяемы через модель
и Django Admin; изменённые поля не перезаписывают исторический маршрут.

Регрессии: `tests/test_domain_remediation.py`, `tests/test_workflow.py`,
`tests/test_concurrency.py`. UI проверяется в `tests/test_ui_remediation.py`.

При изменении только рабочего приоритета ручная очередь и назначение сохраняются.
При изменении категории/типа маршрут пересчитывается; если целевая очередь та же,
действующий подходящий исполнитель сохраняется.

## Ответ при недоступном исполнителе (F24)

Ответ автора сохраняется независимо от назначения. Вопрос получает ответ и
answered_at; фактическая пауза завершается. Для возврата в REVIEW отсутствие
исполнителя допустимо. Для возврата в IN_PROGRESS недействующий исполнитель
заменяется подходящим участником или владельцем той же очереди, с историей
before/after. Если подходящих сотрудников нет, карточка возвращается в REVIEW,
назначение очищается, а `cycle.policy.assignment_resume_status=IN_PROGRESS`
отмечает ожидание восстановления ответственности координатором.

Ранее принятое APPROVED, критерий, план реализации и решение цикла сохраняются.
Просрочка плана продолжает учитываться. Координаторское assign с подходящим
исполнителем возвращает IN_PROGRESS и очищает маркер без нового решения и без
переноса плана. До назначения запрещены повторные approve/decline/acknowledge,
duplicate и новый ask_info. Переклассификация сохраняет маркер; возобновление требует явного
назначения. Отзыв автором уже начатой реализации требует согласования даже во
время такого возврата в REVIEW. Аналогичная защита применяется к resume_info.
